# 示例：把四句用户约束固化为长期规则

本例用于解释审查方法，不是需要每次载入的固定答案。

## 输入与合理结果

用户要求：关键证据足够时交付答案及剩余未知；额外检查说明会改变什么；无新变化不重复查静态事实；不自行把原因分析扩大成迁移或重装。

合理交付：原文或等义短文保存到合适的持久入口，必要时更新相关 skill 的短规则，检查实际写入；报告保存位置与验证边界。规则文件可读回，不等于所有会话必定加载，更不等于下一次任务会遵守。

## 来自一次真实导出的可观察发现

- 约51秒、13次顶层调用完成保存。一次旧文本匹配失败后依据错误回执纠正并成功；这是合理恢复，不能仅因重试就判低效。
- 四句约束被扩成约90行，分散到两个 skill；其中一个 skill 返回体已超过10万字符并溢出转存。支持检查规则膨胀与重复，但不能声称全部返回体都进入了模型上下文。
- 新规则自行增加“环境阻塞交付时可扩大修复范围”的例外，并把它称为授权；阻塞事实本身不产生授权。
- 新规则把进程存在列为静态事实，可能禁止必要的动态复核。
- 最终承诺“以后每个会话自动生效”，但记录只有保存和锚点核对，没有新会话或真实任务验证。

## 可实施的最小修正

保留用户原文；相关 skill 仅保留必要执行规则，避免双份长篇解释。可采用：

> 关键证据足够回答当前问题时，先交付结论与剩余未知。追加检查应能改变相关判断或决策；无相关变化或合理变化可能时，不重复读取已有事实。必要的动态状态复核照常进行。不得自行把原因分析扩大为迁移或重装；环境阻塞不扩大现有授权。报告实际完成的验证层级。

若旧规则要求“一切完全完成前不能汇报”，需区分“解释原因”的交付与“完成修复”的交付；澄清适用范围，而不是继续添加互相竞争的绝对规则。

## 下一次真实验收

用后续一项原因分析任务观察：能否在证据充分后回答、明确真正剩余未知；每个额外检查能否解释其决策价值；必要动态检查是否保留；是否没有自行扩展成环境替换。工具数量只作辅助，不设机械上限。

保存成功与行为改善分别记录。若还未有后续任务，交付“规则已保存，行为效果待验”；不为验证而在生产环境制造故障。
